# Agentic-RAG Benchmark v2：观察依赖规划

**状态：协议草案，未冻结、未执行，没有任何 v2 成绩。** 基于外部提交的 v2 草案（2026-10-12），并按 [`docs/problem-analysis-and-roadmap-20261012.md`](../../../docs/problem-analysis-and-roadmap-20261012.md) 第 5 节修订。v1 文件、注册矩阵、冻结快照和 v1 主指标（Core 70 Strict Task Success）都不改。

## 1. 研究问题

v2 只回答一件事：**在观察依赖任务上，Agent 的额外决策能力相比强的确定性流程，是否值得它的成本。**

| 假设 | 对照 | 内容 |
|---|---|---|
| H1 | B − A | 基于观察结果的确定性多跳检索优于单次 RAG |
| H2 | C − B | LLM 规划相对确定性多跳有额外收益 |
| H3 | D − C | 在可比预算下，逐步动态决策相对结构化规划有额外收益 |

题目需要多跳，不等于必须用 Agent；结论只适用于登记的实现、模型、预算和数据分布。

## 2. 方法

| 臂 | 实现 | 要点 |
|---|---|---|
| A 单次 RAG | `rag` | 一次授权检索 → 选证 → 生成 → 校验 |
| B 确定性多跳 | `deterministic_multihop`（待实现） | 下一跳可以用上一跳检索到的原文实体，但决策由事先写好的通用规则做出；支持多值展开、按日期取版本、条件分支；实体缺失或不唯一时停止。**禁止硬编码 Dev / Test 的实体、事故号、人员或文档 ID** |
| C 结构化 Planner | `planner` | LLM 一次规划、程序执行、中间值逐字核对原文；允许一次重规划时标为 `C_replan1` |
| D 动态 Agent | `dynamic` | LLM 每一步根据观察决定动作与停止 |

`workflow`、`hybrid`、`adaptive` 作为参考臂一并报告，不替代四臂比较。

**公平性：**
- 四臂共用同一索引快照、检索组件、生成模型、验证器和权限、版本范围；
- 硬上限只按调用次数和 token 设，墙钟时间只作安全上限并如实报告；
- 各臂运行顺序按题轮换；
- 生成模型在冻结前由 Dev 上的 2×2 生成层诊断选定。

**任务契约解耦（仅 v2 实验，生产默认不变）：**
- 条件、版本、必答字段等约束对四臂统一保留；
- "契约直接取证并跳到 `finish`"的短路在四臂主实验中禁止；
- 每题记录 `requested_mode`、`selected_mode`、`executed_path`（任务的 `execution` 字段、基准行的 `execution_route`）；`executed_path` 里没有出现对应 Agent 节点的题，不计作该臂执行了策略。

## 4. 标注

每题在 v1 字段之外增加以下字段：
- `dependency_graph`：哪些实体要先观察到才能构造下一跳，以及每条边的合法桥接原文；
- `allowed_evidence_sets`：任一组都足以支持答案的证据组合，不要求检回全部金标文档；
- 诊断标签：`one_shot_gold_doc_gap`（原 `needs_dynamic`，只表示单次检索缺金标文档，不表示必须用 Agent）、`requires_observation_binding`、`branching_after_observation`、`variable_fanout`、`requires_version_resolution`、`counterfactual_group`；
- `review`：审核者、模型或人工身份、理由、是否独立。

## 5. 评分

- **主指标：Strict Task Success。** 以下条件全部满足才算成功：答案正确、必需事实都有原文支持、无关键无支持断言、引用有效、条件与版本语义正确、该拒答时拒答、无安全违规。不要求固定工具顺序，合法的替代路径同样有效。
- **次要指标：**
  - 证据链完整率：必需证据和桥接实体全部进入最终上下文；
  - 中间实体绑定正确率；
  - 有效下一跳率、重复查询、过早停止、过度规划；
  - 成本：调用数、token、P50 / P95。
- **失败归因（取第一个主要失败点）：** 候选缺失、录取丢失、桥接实体或关系错误、策略重复或无效、过早停止、分支或版本错误、证据已到但生成错误、引用无效、授权或运行错误。不能从执行记录里证明的，标 `unknown`。
- **反事实检验：** 成对题只替换上游实体或条件真值，第二跳查询应随之改变；查询里必须包含第一跳实际获得、原题没有给出的实体。
- 未审核的结果保持 null。

## 6. 统计

- 主要分析为新题面 32 题上的 H1–H3：报告配对成功率差值及 95% 置信区间、逐题胜 / 负 / 平数；精确 McNemar 作辅助。
- H1–H3 做 Holm 校正；按题型的结果、消融和路由评估一律标为探索性。
- Test 只有一个虚构世界，不按 world 做聚类 bootstrap。
- 不显著只表示"未检出差异"，不能说"等效"；分母、拒答、超时和执行失败都要列出。

## 7. 消融

最小可行版先做 AB1、AB2、AB4、AB7，其余视结果再做。全部在 Dev 上完成，Test 运行前登记，之后不再增补。

| ID | 对照 | 识别 |
|---|---|---|
| AB1 | A vs B | 程序化多跳的收益 |
| AB2 | B 规则抽取 vs B + LLM 抽取 | LLM 抽取的收益与代价 |
| AB3 | B + LLM 初始计划 | 规划的单独贡献 |
| AB4 | C 单次规划 vs C_replan1 | 重规划的净收益 |
| AB5 | C / D 有无原文实体绑定 | 原文绑定的作用 |
| AB6 | D 规则停止 vs 模型停止 | 过早停止与重复搜索的权衡 |
| AB7 | 4 / 8 / 12 次搜索预算，加上下文上限 | 预算变化下各方法的排序是否改变 |
| AB8 | 规则路由 B→C vs 始终 C | 按需升级的增益 |

**路由评估**在混合题集上进行（Dev47 简单题 + Dynamic Dev），事先登记简单题占 50% / 70% / 90% 三种比例并分别报告；这些是模拟负载，不是真实流量。路由器只在 A–D 的行为可以量化之后再开发。
