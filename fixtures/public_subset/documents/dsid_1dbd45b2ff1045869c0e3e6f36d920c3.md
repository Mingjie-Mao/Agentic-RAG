Add spotless CI bootloader and dependency whitelist heuristics

Motivation: reduce contributor CI latency and noisy rebuilds by seeding the toolchain and caches on-demand and avoiding heavy steps for stable transitive dev-dependencies. This PR introduces a lightweight on-demand 'spotless' CI bootloader that inspects the changed file set and seeds only the minimal toolchain artifacts required for the presubmit run, plus a dependency whitelist heuristic that short-circuits expensive transitive dependency checks for known-stable packages. It also wires a small telemetry probe to measure time and network savings so we can iterate on heuristics. Key outcomes: median first-run CI setup time down ~38% in internal canary, reduced remote-cache pressure for large monorepo builds, and fewer presubmit false-positives caused by devdep churn. Checklist: [x] prototype agent and interface, [x] integrate with existing GitHub actions entrypoints, [x] unit and integration tests for heuristic logic, [x] lightweight telemetry and opt-out flag, [x] documentation and runbook. Notes: this is intentionally conservative—no runtime or product-facing code changes—only CI/tooling and docs. See linked Linear tasks for rollout schedule and canary targets.
