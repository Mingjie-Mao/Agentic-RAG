Introduce lint-bridge and minimal toolchain curator to reduce presubmit duplication

Context and motivation: Over time presubmit runners accumulated near-duplicate lint/test setup code across JS/Go/Python pipelines. This increases flakiness and slows iteration when bootstrapping toolchains or rotating devdeps. This PR introduces a thin "lint-bridge" abstraction and a minimal toolchain curator binary that centralizes devtool snapshots, normalizes env bootstrapping, and provides a lightweight caching layer for presubmit images. Goals: reduce presubmit setup churn, remove duplicate setup scripts, shrink CI image surface area, and provide an opt-in compatibility adapter for legacy jobs.

What this change does (single-pass summary):
- Adds a Go-based toolchain-curator (cmd/curator) that discovers workspace language targets and emits a stable toolchain manifest.
- Introduces lint-bridge shim that exposes a small, consistent CLI (lint-bridge run --profile) used by presubmit workflows.
- Reworks CI workflows to call the curator once per matrix and pass a manifest path into runners rather than running ad-hoc install scripts.
- Adds a minimal Docker light-image for fastest-presubmit path and a fallthrough path for full images.
- Plumbs dep-curation metadata into existing dep-snapshot reports to make aggressive pruning safe.
