credential-stager-and-async-stream-helpers-python-sdk

Context: Several teams reported friction when integrating token rotation and bursty streaming workloads. This PR introduces a CredentialStager utility (lightweight prefetch + lease queue) and an async_stream helpers module to make backpressure-friendly async iterables easier to compose across long-lived streaming sessions. Motivation: reduce auth-related failed requests during token handoff and improve ergonomic composition for consumer code (less boilerplate around cancellations, reconnection hints, and graceful drains). Design goals: (1) keep public surface minimal and opt-in, (2) reuse existing credential interfaces so cross-SDK parity is achievable, (3) add telemetry hooks for future rollout. What this PR does: - Add redwood_sdk/credentials/stager.py (CredentialStager): prefetches refresh tokens, exposes acquire/lease/release semantics, supports pluggable backoff policies. - Add redwood_sdk/streams/async_helpers.py: provides async_partitioned_iter, drain_with_timeout, and a small stream combinator (zip_async) that preserves cancellation semantics. - Wire CredentialStager into streaming client internals as an optional parameter (client ctor kwarg: credential_stager). - Add docstrings, examples, and migration notes in docs/streaming.md and examples/streaming/credential-stager-example.py. - Tests: unit tests for stager lease behavior, integration test that simulates token expiry during an ongoing stream, and a small e2e that exercises reconnection with pre-warmed credentials. Related: coordinated with TS/Go SDK maintainers to align API shapes (see ENG-1292). Rollout: default behavior unchanged; customers must opt-in to enable stager via new kwarg. Migration: guide included to show how to pass existing credential providers into the stager.
