Minimize lint boot time and introduce dependency stitcher

Motivation: Presubmit/lint startup latency has been a recurring source of slow feedback (ENG-4876). On average, developer CI workflows saw 25-60s extra boot time on cold runners due to devdep installs, heavy node/npm setups, and monorepo-wide tool initializers. This PR introduces two complementary changes: (1) a lightweight 'dep-stitcher' utility that builds a minimal compatibility map for dev dependencies and (2) a refactor of the lint presubmit entrypoint to an incremental loader + selective devdep fetch.

What changed (high level):
- dep-stitcher: a tiny Go-based tool under tools/dep-stitcher/ that collects package metadata from package.json/Pipfile/pyproject for workspace packages and emits a compact stitch.json that maps top-level devdeps -> pinned shims. The stitch file is created in CI prewarm and used to avoid expensive install work for many repos.
- presubmit bootstrap refactor: replaced monolithic scripts/presubmit/bootstrap.sh with scripts/presubmit/boot-incremental.{sh,py} that: (a) consult stitch.json, (b) prime only the subset of devdeps required for changed paths, (c) reuse the shared presubmit base image with layered caching.
- CI template updates: added a new presubmit step ci/presubmit-primer that runs 'dep-stitcher --scan' on the changed subgraph and caches stitch.json keyed by repo+stitch-hash. The presubmit job now has an early exit path when nothing relevant changed.
- Tooling: introduced a small cache warm helper and documentation: docs/ci/presubmit-boot.md.

Why this approach: The goal is pragmatic: reduce no-op work and accelerate feedback. dep-stitcher is intentionally conservative (no automatic upgrades) and outputs a deterministic map so cache keys remain stable. The incremental loader keeps behavior transparent for teams while reducing unnecessary installs.

Risk and rollout: The changes are opt-in initially — teams add a small pointer to cache in their CI or allow the presubmit template to run for them. No automatic changes to production-serving code. The dep-stitcher runs only in CI prewarm and outputs artifacts stored in workspace caches; it never mutates repo lockfiles.

How to validate post-merge: Run the new presubmit template against a few representative repos (redwood-examples, redwood-sdk-typescript) using --dry-run and compare cold-run vs warmed-run timings. Early tests showed ~35-50% presubmit boot time reductions on node-heavy targets.
