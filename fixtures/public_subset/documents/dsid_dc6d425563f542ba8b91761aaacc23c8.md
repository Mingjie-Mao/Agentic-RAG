catalog: introduce compatibility matrix + queryable pricing/limits filters for model-list API and OpenAI-compat harmonization

Motivation: product and SDK teams need a single, queryable model-list endpoint that surfaces model capabilities, OpenAI-compat flags, and pricing/limits metadata so clients can filter for models that support streaming, function/tool calling, structured output, and particular compatibility layers. This PR adds a compatibility matrix to the model catalog API, exposes pricing_tier and token_limits fields for server-side filtering, and harmonizes the OpenAI compatibility flags across the HTTP API and SDKs.

What this changes: added query parameters: ?capability=streaming|functions|structured_output, ?compat=openai|redwood, ?pricing_tier=free|standard|enterprise, ?max_context=<int>. The model-list response now includes a top-level capabilities list (strings), a compatibility object flattened into compatibility_flags (strings), and pricing_tier and token_limits (max_input_tokens, max_output_tokens). We also add a compatibility_version string for models with multiple compat modes.

Migration notes: clients using the old openai_compat boolean should migrate to compatibility_flags= ["openai_v1"] or use compat=openai query param. SDKs updated in this PR provide helpers get_compatibility() to map legacy fields. Backwards compatibility: the endpoint still returns legacy openai_compat boolean for one release cycle (deprecated).

Testing and rollout: unit tests added for route and handler, integration tests cover query combinations, and a small canary in the hosted catalog was run for 48h. Docs (api/model_catalog.md) updated with examples.
