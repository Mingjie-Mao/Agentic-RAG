rework airgap OCI index to support multi-registry catalog + atomic upgrade preflight

Motivation: Customers operating in highly regulated on-prem environments requested better multi-registry support and stronger artifact verification for air-gapped installs. Existing OCI index files assumed a single mirrored registry and had limited checksum/sig metadata, which made staged upgrades fragile when registries were synchronized in different orders. This PR rewrites the airgap OCI index format and implementer tooling to: 1) allow a single index to reference multiple registries (primary/mirrors/region-specific), 2) embed SHA256 checksums and optional PGP-signed manifest blobs, and 3) provide an atomic preflight that validates the complete set of registry endpoints before bootstrap or upgrade.

What this PR does (high level): Replaces the previous flat index generator with an orchestrated index writer that emits a consolidated oci-index.json containing per-image entries with an ordered list of mirrors, checksum, and optional signature URL. Adds a new Terraform module (registry-sync-job) that spawns a small, short-lived Kubernetes Job to verify registry reachability and to prefetch a minimal image ancestry list. Adds Helm chart pre-install and pre-upgrade hooks to seed the local registry cache (if present) and to run the same verification logic inside the target air-gapped environment. Adds a new --verify / --sign flags to the offline bundler cli to optionally sign indexes and to produce a compact 'index.lock' used by the installer for atomic apply.

Files changed (high level): sources/redwood-private-installer/pkg/index/serializer.go (new multi-registry writer), cmd/airgap-bundler/main.go (verify/sign options and index.lock emission), terraform/modules/registry-sync-job (new module + examples), charts/redwood-installer/templates/hooks/preseed-job.yaml (helm hook and job template), docs/airgap/index-format.md (spec and upgrade notes), tests/integration/airgap_index_test.go (end-to-end index generation/verify).

Rollout plan: Cut this as an opt-in change behind the bundler flag --format=v2.0. Existing v1 indexes will continue to be accepted by the installer for one release cycle. The plan is to: (1) ship bundler with v2.0 support and docs, (2) ship installer with read-compat and an optional --require-index-lock flag, (3) enable --require-index-lock by default in the next minor once customers have migrated.

Testing: Unit tests for serialization and checksum/signature verification were added. Integration test spins up a freighter-registry (local test aid) and two mock mirror endpoints to validate mirror ordering and failover. Terraform module was tested using a lightweight kind cluster in CI to ensure the registry-sync-job works with imagePullSecrets and private registries. CI matrix included alpine/sles bundles to ensure packaging logic is distro-agnostic.

Backward compatibility and rollback: The installer detects v2.0 index and falls back to v1.0 semantics if --require-index-lock is not set. If a customer attempts an upgrade with partial registry availability, the installer fails fast (preflight failure) and emits an actionable error listing unreachable endpoints and missing checksums. Rollback instructions are included in docs/airgap/upgrade-rollback.md; the Helm hook uses annotations to ensure jobs are garbage collected on rollback.

Security considerations: Signatures are optional but recommended for regulated deployments. The bundle signer supports in-memory KMS and local PGP key files. The Terraform module runs with a minimal serviceaccount bound only to create Jobs and read Secrets. The preseed job avoids pulling large images by leveraging manifest-only requests when registries support HEAD/pull-by-digest.

Related work: this builds on prior airgap index work (see SUP-1938) and the offline-bootstrap delta snapshots project but diverges by focusing on multi-registry and verification-first upgrades.

Notes: The new index format is documented and includes migration examples. The change was kept small by reusing existing bundler tar layout; only the index.json and index.lock semantics changed.
