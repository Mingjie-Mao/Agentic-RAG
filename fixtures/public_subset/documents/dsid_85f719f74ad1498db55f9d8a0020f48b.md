Introduce intent-aware release outline and rollback telemetry pipeline

Motivation: Release notes generated during onboarding were too generic for intent-driven model changes (e.g. feature toggle, safety tweak, perf upgrade). This PR introduces an intent-aware release outline generator that maps onboarding metadata and profile diffs into structured release sections (Behavioral changes, Safety mitigations, Performance/Cost tradeoffs, Rollout guidance). It also wires a rollback telemetry pipeline that captures sampled inference traces, activation of safety gates, and error-rate deltas so we can automate targeted rollbacks and produce a rollback playbook. What changed: 1) schema: added release.intent and release.impact_hint fields to model metadata and onboard manifests; 2) new service: release-outline-generator that consumes profiles and intent hints to produce a human-readable outline and machine-readable rollout plan; 3) telemetry: rollback-exporter sidecar that collects sampled traces and produces aggregated rollback signals to the runbook service; 4) CLI: onboard --intent flag and preview command to generate a draft release outline locally; 5) tests and docs: unit and integration tests for schema validation and a new doc page in docs/onboard/release-guides.md. Backwards compatibility: old manifests continue to work but will get a generated default intent of "general" when missing. Rollout and safety: default sampled telemetry rate is conservative and can be tuned per-customer. Migration notes: migration script provided to backfill intent fields from profile tags.
