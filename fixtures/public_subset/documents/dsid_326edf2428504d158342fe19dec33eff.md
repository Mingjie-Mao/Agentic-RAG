Adaptive warm-pool sizing and cluster budget apportioner

Motivation: Dedicated clusters suffer from tail latency and cost overhead due to cold-started worker processes and idle GPU spin-up. Static warm-pool sizes either waste capacity or fail to prevent bursts. This PR implements an adaptive warm-pool controller plus a cluster-level budget apportioner that distributes reserved idle capacity across clusters and tenants based on short-term demand signals and priority weights. Goals: 1) reduce tail latency for bursty workloads on Dedicated without large static reservations; 2) keep unit cost neutral by reclaiming idle warm capacity when not needed; 3) expose safe knobs for ops and allow gradual rollout via flags. Summary of changes: - controller/autoscaler: add AdaptiveWarmPoolController implementing proportional target sizing using short-term request rate, recent allocation utilization, and tenant priority score. - controller/apportioner: new ClusterBudgetApportioner that computes per-cluster warm allocations from a global warm budget with smoothing and minimum guarantees. - runtime: add warm-pool lifecycle management to node-agent to pre-warm containers and evict according to LRU+utilization heuristics. - metrics/logs: export warm_pool_target, warm_pool_allocated, warm_pool_utilization_pct, apportioner_score, apportioner_decisions for tracing. - docs/ops: operator guide for tuning warm thresholds and migration notes. - tests/sim: simulation harness and unit tests covering demand spikes, starvation scenarios, and rollback. Rollout plan and safety: default behavior remains off for existing clusters. New clusters created after the release will have the adaptive warm pool disabled by default; ops can enable per-cluster with a safety cap and gradual ramp (10% warm budget -> 50% over 24h). Controller includes backpressure to avoid over-provisioning when API server signals capacity pressure. Linked work: ENG-2147. Checklist: - [x] Controller implementation - [x] Apportioner algorithm and smoothing - [x] Simulation harness and unit tests - [x] Metrics and dashboards - [x] Documentation and ops guide - [x] Feature flag and rollout strategy
- Adds adaptive warm-pool sizing that reduces cold-start latency while improving GPU utilization across dedicated clusters.
