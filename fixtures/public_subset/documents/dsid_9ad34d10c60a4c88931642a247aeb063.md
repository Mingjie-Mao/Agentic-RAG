Introduce defaults-suggester: heuristic profiles for batching, cache TTLs and quantization presets

Context: Teams repeatedly ask for sensible defaults for batching, cache TTLs and quantization when onboarding models to Redwood. Currently defaults live in multiple places and require manual tuning with evals and internal heuristics. Goal: ship a small, auditable suggestion system that observes recent workload signals and proposes conservative default profiles for batching.window_ms, batch_size caps, prefix/KV cache TTLs, and quantization presets. The suggester is opt-in by default and produces human-readable suggestions surfaced in the Console and via a new API endpoint.

What this PR does: 1) Adds a lightweight offline heuristic engine (defaults-suggester) that consumes short-term aggregated telemetry (per-route QPS, median latency, 50/95/99 latency quantiles, token length distribution) and maps to a ranked set of suggested profiles. 2) Introduces a new API: POST /optimize/v1/suggestions which returns JSON suggestions with confidence scores and an explanation string. 3) Wire up Console: a Suggestions panel on per-route settings with an Apply & Preview flow that shows estimated unit-cost delta and latency impact. 4) Add a gated runtime flag so the runtime can accept a profile payload for immediate application (useful for Dedicated/Private workflows). 5) Provide a small set of canonical profiles (conservative, balanced, aggressive) for batching and quantization, plus TTL presets for prefix/KV caches. 6) Add end-to-end test coverage and benchmark harness runs comparing before/after for representative traffic shapes.

Design notes and trade-offs: - The engine intentionally errs conservative: suggestions will never increase batch window beyond a route-level safety cap derived from SLA settings. - Quantization suggestions prefer per-model family presets (e.g., OPT/GPT-like) and include fallbacks; we do not auto-apply quantization in-host, suggestions only. - Telemetry ingestion is opt-in; customers can disable telemetry for suggestions in account settings. For Private installs the suggester can be run locally against their telemetry export. - Suggestions include an estimated unit-cost delta computed from our unit-econ model; we expose the formula in the Console and include the prompt/eval link so teams can validate quality impact.

Testing: - Unit tests for mapping heuristics and profile ranking. - E2E test simulating three traffic shapes (short chat, assistant longform, embeddings micro-bursts). - Benchmarks: microbenchmark harness run on a c6g-xlarge-equivalent cluster with representative models showed median latency change within +3% for conservative profiles and unit-cost reduction up to 24% for balanced profiles on nuclear workloads. Results attached to the CI artifact and linked in the console patch notes.

Rollout plan: feature gated. Step 1: merge behind feature flag and enable suggestions only for internal org and canary customers. Step 2: collect feedback for 2 weeks. Step 3: enable Console UI for self-serve with telemetry opt-in prompt on first usage. Step 4: document caveats and add guided eval for teams that accept aggressive quantization suggestions.
