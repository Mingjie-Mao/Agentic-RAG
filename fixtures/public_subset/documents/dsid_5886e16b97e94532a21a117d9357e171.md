Introduce tenant KMS delegation chaperone and audit plumb for region-bound key flows

Motivation: Customers operating under strict data residency policies requested stronger guarantees that operator actions and KMS delegations cannot move tenant keys or allow key use outside the tenant's pinned geozone. This PR introduces a 'delegation chaperone' service and an audit plumbing surface that together (1) enforce region-bound delegation rules at the control-plane boundary, (2) sign and canonicalize KMS delegation events for downstream audit retention, and (3) provide a safe rollout path compatible with existing RBAC v2 mappings. Design summary: the delegation chaperone sits in the control-plane path where service-to-KMS delegation tokens are minted. It verifies tenant residency assertions and the operator's scope (via RBAC v2 claims), applies region-pin policies, and either emits a canonical delegation proof (signed HMAC + metadata) or rejects the delegation. All delegation proofs are fed to the new audit-plumb endpoint which normalizes events and appends a proof-hash header used by the downstream audit-archiver. To minimize blast radius the chaperone is opt-in via feature-flag and supports a shadow mode that only emits proofs but does not block delegations. Backwards compatibility: when disabled the chaperone is a no-op; audit consumers will ignore missing proof headers. Key UX: operators will see explicit failure reasons and a remediation link when a delegation is rejected. Checklist: - [x] Control-plane middleware to validate tenant geozone claim and operator RBAC v2 scope - [x] Proof envelope format (versioned) and HMAC signer using service KMS key - [x] Audit plumb endpoint and migration shim for legacy audit forwarder - [x] Config flags (enable/shadow/whitelist) exposed in operator console and helm values - [x] Unit tests for policy matcher and proof envelope - [x] Integration tests exercise cross-region and shadow scenarios - [x] Add metrics and alerts for rejected delegations and proof generation latency Rollout plan: stage on canary control-plane -> opt-in small tenant cohort (data residency customers) -> enable shadow mode globally -> flip to enforcement after 2 weeks of zero rejects -> add to Dedicated onboarding checklist. Migration notes: existing tenants can be added to a whitelist via tenant annotation until they upgrade their operator bundles. Security review: HSM-backed signer integration uses existing KMS wrapper; signing key access is restricted by operator-role binding. Performance: measured at canary, proof generation adds median ~4ms and p99 < 15ms under a 200rps synthetic workload. Observability: added delegation.chaperone.proof_generated, delegation.chaperone.rejected, and delegation.chaperone.latency.histogram; traces include a proof_id and tenant_id tag. Operational playbook: on an enforcement failure validate tenant-geozone claim, check RBAC role-template mapping, and verify that the chaperone is not in shadow mode before contacting SRE. Related work: builds on ENG-7321 (rbac v2 rollout) and ENG-8800 (audit archival redesign).
