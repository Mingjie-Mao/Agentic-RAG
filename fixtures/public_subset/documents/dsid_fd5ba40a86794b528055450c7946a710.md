introduce-tenant-scoped-signature-header-and-stream-resilience-adapter

Motivation: Several customer investigations showed intermittent streaming disconnects when mutable auth headers (project-scoped nonces) were proxied through intermediate gateways. We also observed complexity in multi-tenant setups where a single X-Project-Nonce-like header was too coarse (project vs tenant/org). This PR introduces a tenant-scoped signature header and an adapter that normalizes legacy nonce headers into the new signal for streaming handshakes and function/tool-call signing, plus conservative resiliency defaults for streaming connections. Goals: 1) Add a stable header for origin-verified tenant-scoped signatures (X-Redwood-Tenant-Signature) that can be used for streaming and tool/function call attestation; 2) Provide a compatibility adapter that accepts legacy project-nonce variants (X-Project-Nonce, X-Redwood-Nonce) and translates them into the new header during a canary rollout; 3) Harden the streaming handshake so that auth header refreshes and prefetches do not trigger connection resets; 4) Expose minimal CORS headers required by browser-based streaming clients and document migration steps. Implementation details: - New header X-Redwood-Tenant-Signature: base64url(signature||metadata) where metadata includes tenant_id, nonce_ts and algorithm id. The runtime validates signatures against tenant public keys sourced from the tenant key registry. - Adapter layer pkg/server/auth/tenant_adapter.go: on ingress, if X-Redwood-Tenant-Signature present -> validate and annotate request context. If missing, attempt legacy fallbacks in this order: X-Redwood-Nonce -> X-Project-Nonce -> Authorization: Project <token>. Legacy fallbacks are opt-in via config.auth.tenant_adapter.enable_legacy_fallback=false by default. - Streaming handshake changes: keep-alive semantics updated to tolerate up to 3 header-refresh frames within 10s without closing the multiplexed stream. When a header refresh occurs, the adapter will attempt an atomic reauth that preserves the stream state unless the signature check fails. - Tool/function call signing: function/tool-calls that are proxied to plugins now carry X-Redwood-Tenant-Signature and a signed-prefetch token header Sec-Redwood-Prefetch. Prefetch is short-lived and strictly single-use. - CORS: add Access-Control-Expose-Headers: X-Redwood-Tenant-Signature, Sec-Redwood-Prefetch and ensure Access-Control-Allow-Credentials is true for private deployments by default. - Compatibility & rollout: feature gated behind runtime flag with a staged rollout: 10% canary, 50% expanded, then 100% once metrics (401 rate, stream resets) are stable. See rollout plan below. Tests & validation: unit tests for adapter logic and signature format; e2e in perf-canary test harness exercising streaming reconnect scenarios with legacy and new headers; integration test that verifies toolcall signing preserved when proxying through the compatibility adapter. Migration notes (single continuous guidance): New clients should sign requests using tenant keys and send X-Redwood-Tenant-Signature. If you cannot rotate immediately, enable the legacy adapter on your private control plane and configure the short deprecation window (60 days recommended). Operators: update tenant key registry to publish public key fingerprints; monitor metric auth.tenant.signature.fail_rate and streaming.handshake.reauth_count. Rollout Plan: - Phase 0 (canary): enable adapter on 10% of hosted traffic for two weeks - Phase 1: expand to 50% and keep for one week - Phase 2: 100% and, after 48h stability, flip enable_legacy_fallback=false by default - Full deprecation of legacy nonce headers after two months with customer notices.
