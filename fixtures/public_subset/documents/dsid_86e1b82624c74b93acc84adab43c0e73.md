graceful-redistribution-proxy-with-telemetry-led-holdoff

Adds telemetry-driven regional redistribution proxy to delay and soften cross-region traffic shifts during degradations. Feature-gated and backward compatible; enables soft-tenant quarantine and sticky backoff to prevent oscillation.
Motivation: During multi-region degradations we've observed aggressive redistribution of requests that causes cascading cold-starts and transient overloads in healthy regions. This PR introduces a telemetry-led 'redistribution proxy' that coordinates cross-region traffic shifts using live health probes and tenant-scoped sticky backoff tokens. Behavior: when a region is detected as degraded, the proxy delays full redistribution until a health probe window confirms sustained degradation (configurable, default 30s), and redistributes incrementally using weighted ramp steps. A tenant soft-quarantine path is available: tenants exceeding error-rate SLOs are diverted to degraded-mode routes (slowpath variants or cached responses) rather than immediate eviction. Sticky backoff prevents rapid reopen/close oscillation by holding per-tenant backoff tokens with exponential decay. Implementation summary: - New runtime component services/router/redistribution_proxy.go that implements the decision state machine and probe orchestration. - Telemetry hooks added to telemetry/metrics/collector.go and new tracing spans (redistribution.proxy.*). - Tenancy integration via infra/tenancy/quarantine_manager.go to apply soft quarantines and record reasons. - Config flag feature_gates.regional_redistribution_proxy with rollout config in config/defaults.yaml. - Lightweight dashboard and runbook additions under docs/runbooks/regional-degradation.md and integrations/console/dashboards/regional_redistribution.jsonnet. Tests: unit tests for the state machine and probe replay (services/router/redistribution_proxy_test.go), an integration harness that simulates staggered region failures, and synthetic load tests to validate ramping semantics. Rollout plan: gated by feature flag; start with canary in us-west-2 for 1% of traffic, monitor E2E SLOs (p95 latency, 5xx rate), watch new metric redistribution.proxy.handoff_delay_seconds.p50/p95 and tenant.quarantine.count. If a regression is observed, flip feature flag off or use the emergency throttle gate to disable redistribution globally. Backwards compatibility: API surface unchanged; when the feature flag is off the proxy is a no-op. Safety: added a kill switch that immediately reverts to pre-PR routing; introduced a conservative default holdoff (30s) and per-tenant max ramp (20% per minute). Related: ENG-4287 (regional stability), ENG-4321 (tenant soft-quarantine).
