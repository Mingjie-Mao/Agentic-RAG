introduce-journey-replayer-cli-with-session-serializer-and-offline-probe-harness

Motivation: debugging RAG flows during authoring is painful for teams working offline and on CI. This PR adds a compact journey replayer CLI that records interactive RAG sessions, serializes them to a portable .jrny (JSONL+metadata) format, and replays them deterministically with configurable offline probes (tool stubs, latency fuzzers, deterministic RNG). The goal is a lightweight local-first workflow for reproducing issues, running smoke assertions, and generating telemetry snapshots for CI-based quality gates.

What this PR does:
- Add a new CLI 'jrny' (Rust + tiny node shim) under quickstarts/jrny-cli/ that can capture and replay sessions.
- Introduce session serializer format (compact JSONL with header metadata + deterministic seeds).
- Offline probe harness that lets authors register tool stubs, response fixtures, and latency profiles to emulate production toolchains.
- Examples: two templates (simple-qa and multi-tool-orch) and a CI job sample that runs a headless replay with assertions.
- Docs: quickstarts guide and step-by-step authoring tutorial in quickstarts/jrny-cli/README.md.

Design notes and tradeoffs: chose a compact JSONL format to keep files human-inspectable and shippable as artifacts. The Rust binary was selected for small, dependency-free cross-compiled binaries; the Node shim limits auth surface area and reuses existing SDK credential loading. The probe harness intentionally focuses on deterministic tooling (fixtures + latency profiles) rather than full service emulation; that keeps CI runs fast and predictable.

How to use (short):
1) cargo build --manifest-path quickstarts/jrny-cli/Cargo.toml --release
2) ./target/release/jrny record --out examples/simple-qa.jrny --sdk-config ~/.config/redwood.json
3) ./target/release/jrny replay --in examples/simple-qa.jrny --probe latency:50 --assert \"final_answer contains \\\"Paris\\\"\"
