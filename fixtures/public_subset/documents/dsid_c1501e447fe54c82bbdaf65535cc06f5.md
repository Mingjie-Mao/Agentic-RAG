openai-bridge-forward-client-rng-hints-and-annotation-headers-for-responses-vnext

Motivation: newer OpenAI Responses-style clients are starting to pass lightweight RNG/determinism hints and inline annotations in requests; when we bridge those requests into Redwood's runtime we must preserve the client's intent across streaming reassembly, tool/function-call handoffs, and into response metadata. This PR implements a compatibility layer that: 1) recognizes common client-side RNG/determinism fields (rng_seed, client_seed_hint, deterministic_hint) and forwards a normalized header (X-Redwood-Client-RNG) into the serving path so the runtime can apply a deterministic sampling policy when requested; 2) captures client annotations (annotations, client_metadata, x_annotations) and forwards them as structured headers (X-Redwood-Annotations) and also injects them into the Responses-style response envelope under response.metadata.annotations so downstream consumers (SDKs, loggers) can observe them consistently; 3) ensures that streaming chunks carry sequence and rng context so that streamed partial chunks and final tool_call events are stitched with the same RNG context and annotation set; 4) adds a translation shim so older OpenAI-compat calls that used "seed" boolean or numeric flags still map into the new header scheme.

What changed (high level): added an adapter module that normalizes incoming OpenAI-compatible fields into a small set of internal headers, extended the streaming reassembly path to keep a per-request rng_context object through partial-chunk buffering and toolcall handoffs, and updated the tool-calling plumbing so tool invocation events receive the X-Redwood-Annotations and X-Redwood-Client-RNG headers as part of the call payload. Also added unit + integration tests, docs updates, and CI checks for streaming stability under chunk loss.

Compatibility notes: This is additive for most callers. Default behavior is unchanged unless a client sends determinism/rng hints or annotations. For customers relying on previous implicit RNG behavior, the runtime still falls back to random sampling when X-Redwood-Client-RNG is absent. The header values are advisory; enforcement requires opt-in via route config (see notes in docs/openai-compat.md). Linear: ENG-4129.
