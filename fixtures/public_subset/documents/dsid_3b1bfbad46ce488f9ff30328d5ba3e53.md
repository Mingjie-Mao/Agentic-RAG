Introduce compact footprint estimator and sparse changelog drafter

Summary: Adds a lightweight 'footprint estimator' and a sparse changelog drafter to make model intake faster and release notes more actionable. The footprint estimator runs a compact probe (tiny synthetic prompts + static metadata heuristics) to estimate memory footprint (vRAM), quantized size, expected token throughput for common batch sizes, and recommended deployment profiles. The sparse changelog drafter consumes the estimator's delta and telemetry-sampled performance metrics to auto-generate short release notes focused on: performance deltas, memory/size regressions, affinity/quantization suggestions, and a confidence score.

Motivation: Model onboarding currently produces large verbose changelogs and requires manual effort to surface runtime-impacting changes (size/regression/compat). Teams asked for a quick signal that they can show to infra & SRE during early review and that can be surfaced in rollouts. This PR provides two instrumentation/automation hooks that are conservative in scope and cost-aware: a compact estimator for first-pass estimates, and a sparse drafter to surface only meaningful diffs.

What this changes (high-level):
- cmd/registry/cli/footprint.go: new CLI command 'rb-reg footprint estimate <model>' with flags for --probe-sample-rate and --quant-modes. Outputs a single-line JSONL footprint and a human summary.
- service/api/footprint_handler.go: adds POST /api/v1/models/:id/footprint which triggers a staged probe run or returns last cached footprint.
- ingestion/prober/compact_probe.go: compact probe harness (max 3 synthetic requests, deterministic seed) plus heuristics for deriving memory footprint from tokenizer+params+quantization settings.
- changelog/drafter/sparse_drafter.go: logic to compute delta between two footprints+telemetry and render a concise changelog with 'impact buckets' (size, latency, compatibility) and suggested rollbacks or mitigations.
- templates/changelog/compact.md: human-friendly template for sparse changelog snippets.
- docs/model-intake/footprint.md: user-facing docs and recommended thresholds for Dedicated vs Hosted routing.
- tests/*: unit tests for estimator heuristics and drafter ranking logic.

Backward compatibility and safety:
- The estimator runs only when explicitly invoked, or when intake is configured to run probes (opt-in default). The API endpoint respects per-tenant rate limits and a model-level opt-out. Footprints are cached by default (5 minutes) to avoid probing storms.
