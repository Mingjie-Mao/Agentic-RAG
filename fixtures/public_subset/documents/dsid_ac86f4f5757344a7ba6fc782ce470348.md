Add multi-dimension token telemetry and alert coalescer (log contextualizer + dashboard)

Motivation: Production customers report intermittent long-tail token latency spikes and noisy alerting where multiple correlated signals fire separately. This PR introduces a compact multi-dimensional token telemetry pipeline that joins token-level timing, model variant, route, and sampler cohort; a lightweight in-memory alert coalescer to group related alerts by token provenance; and a log contextualizer that attaches a minimal set of relevant logs to sampled traces for faster Triage.

What this PR does (high level):
- Adds a token multi-dimension collector that emits compact rollups keyed by (tenant, route, model_variant, token_position_bucket, cohort_id) for real-time dashboards and downstream aggregation.
- Introduces an Alert Coalescer (in alerts/) which takes near-real-time alert events and groups them into incidents when they share token provenance within a sliding window. Coalescer supports configurable grouping rules and suppression windows.
- Implements a Log Contextualizer that, given a sampled trace/span, attaches the nearest log lines (service, level, 2 preceding, 2 following) and annotates them with token-affinity metadata to make long-tail traces actionable.
- Adds a curated observability dashboard (dashboards/token_telemetry_dashboard.json) with a multidimensional explorer, cohort heatmaps, and a compact per-tenant cost/latency sparklines panel.
- Provides migration and rollout strategies: feature flag gated collector and coalescer, backward-compatible protobuf change, and a gradual rollout plan in 3 stages (shadow -> gated -> default).

Design notes:
- Collector emits compact protobuf records (v2) to the existing telemetry kafka topic. The schema is strictly additive and the collector runs as an optional sidecar under the "telemetry" daemonset.
- Coalescer is implemented as a stateless microservice that maintains short-lived grouping windows in a bounded LRU cache; grouping keys are hashed to ensure deterministic coalescing across instances. Grouped alerts are enriched with a representative trace id and sample logs.
- Log contextualizer hooks into our trace sampler and operates asynchronously: it performs a small log-lookup query against the log-index service and attaches up to 5 contextual lines to trace metadata. For performance we use a cached index lookup with 30s TTL.

Testing & validation:
- Unit tests for collector encoding/decoding and coalescer grouping rules.
- End-to-end simulation harness that replays production-like token sequences and validates that coalescer reduces alert noise by grouping correlated alerts (added integration test harness under tests/observability/replay/).
- Load-tested the collector sidecar under synthetic traffic (peak QPS ~25k requests/s) using the benchmark lab harness; informs batching defaults.

Operational runbook highlights:
- Feature gated via config: observability.token_multi_dim.enabled and alerts.coalescer.enabled. Both default to false for the initial rollout.
- Rollout plan attached: 10% traffic shadow for 24h, 25% gated for 48h with active monitoring, then 100% gated and turn on coalescer.
- Dashboard includes an "upgrade safety" panel showing the proportion of records that use v2 schema, collector error rates, and coalescer grouping rates.

Backward compatibility:
- The protobuf schema is additive; consumers that don't understand the new fields will ignore them. The coalescer can emit either the old alert shape or an enriched incident envelope depending on a compatibility mode.

Risks & mitigations:
- Additional telemetry volume: collector uses delta-encoding and configurable downsampling. Default sampling preserves tail fidelity while bounding volume.
- Latency impact: contextualizer is async and only runs for sampled traces; cache reduces external lookups.
- Alert noise regressions: coalescer is off by default and includes a simulator to validate grouping rules against historical alerts.
