Neon-orchestrated attention: hybrid Flash + kernel tiler with lazy-KV streaming

Summary: Introduces a neon-orchestrated hybrid attention path that combines a lightweight FlashAttention-style fast path with a tiled microkernel fallback. The patch adds a tiler that decides at runtime between (1) the optimized Flash micro-path for dense short sequences and (2) a new neon-prefetch tiled kernel for long contexts and odd sequence-lengths. Additionally this PR implements a lazy-KV streaming integration: instead of allocating/evicting large KV pages eagerly, the runtime streams KV slabs on demand and performs background prefetch with priority hints from the batcher. Motivation: our production traces show two dominant sources of per-token latency and cost: kernel selection overhead for mixed-length workloads and expensive full-KV swaps on long-context workloads. The hybrid path reduces kernel dispatch overhead and keeps the fast Flash path density benefits while the tiler maintains throughput on longer sequences. Design notes: - Kernel Tiler: a lightweight heuristic that computes tile sizes based on seq_len, k/v cache hits, and device utilization. Tiler exposes hints to the scheduler (tile_size, prefetch_priority, use_flash_path). - Flash micro-path: minimal changes to the existing Flash bridge to support neon-friendly memory layout and allow partial-row processing for non-4x head dims. - Neon tiled kernel: a new microkernel optimized for moderate tile sizes (32..256) with streaming prefetch and FP16 accumulation; includes an in-kernel rotary index remap to avoid extra memory passes. - Lazy-KV streaming: KV is broken into logically contiguous slabs. When a request needs a slab not present, we schedule an async prefetch and continue with partial KV (best-effort) to maintain tail latency. Background prefetching uses LRU+priority hints from the tiler. - Scheduler integration: continuous-batcher emits per-request hints (hot_token_prefix, expected_future_tokens) so the runtime favors coalescing requests that share KV slabs. - Fallback semantics: graceful fallback to the tiled kernel if flash_path fails or when the tiler estimates minimal benefit. Implementation touches: serving/runtime/tiler/* (core tiler & heuristics), serving/runtime/kvcache/streamer.* (lazy slab manager + prefetch worker), serving/runtime/kernels/neon_tiled_attn.* (new kernel), serving/runtime/kernels/flash_bridge adjustments, tests/perf/bench_attn_tiler.py, docs/attn_tiler.md. Testing & benchmarks: - Microbenchmarks across sequence lengths 8..16384, heads 8..64, model dims 1024..6144. - Canary on dedicated pools (pool-attn-4g). Results (canary): p50 latency -6%, p95 latency -12% on mixed-length workloads (avg seq ~512), throughput +18% on long-context workloads, token-cost -9% (due to fewer KV churns). Rollout plan: canary to 5% dedicated capacity for 48h, monitor tail latency, KV cache miss rate, memory OOMs. If no regressions, gradual increase over 7 days. Migration notes: no API changes. Config flags: runtime.tiler.enabled (default: true), kvcache.lazy_streaming (default: false) — kvcache.lazy_streaming off by default during initial rollout. Backwards compatibility: existing model pins and rollouts remain unaffected.
