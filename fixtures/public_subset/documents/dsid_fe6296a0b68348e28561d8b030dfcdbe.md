quantized-path-orchestrator: unify INT8/FP8 smoothquant + dequant-fusion scheduling

Motivation: We have accumulated several ad-hoc code paths to support INT8 and FP8 inference (smoothquant transforms, dequant fusion, and microkernel variants) which complicate scheduling, KV-cache alignment, and continuous batching. This PR introduces a modest orchestration layer (quantized-path-orchestrator) that: 1) makes explicit path selection rules for INT8 vs FP8 vs full-precision based on model metadata and runtime signals; 2) merges the dequant-fusion decision logic into the scheduler so fused dequant can be applied when it yields end-to-end token-cost wins; 3) aligns KV-cache slot allocation across quantized variants to avoid cache fragmentation and redundant copies; and 4) plugs path-aware continuous-batching heuristics so batch formation respects quantization boundary constraints. Summary of changes: consolidated path routing tables under runtime/quantized/orchestrator; added a small policy DSL to encode compatibility (e.g., supports_smoothquant, requires_dequant_fusion, kv_alignment_hint); extended the runtime scheduler to query the orchestrator when deciding batching windows and token coalescing; added fast-paths in the int8 microkernel launcher to accept fused-dequant buffers to avoid extra memcpy; added unit and e2e perf tests and a canary rollout gated by a feature flag. Design goals: reduce duplicated branch logic across kernels, avoid KV-cache churn when mixing variants, preserve latency SLOs while improving throughput and token-cost. Known constraints: full FP8 support requires newer cuDNN kernels on some clouds; the orchestrator has a conservative default policy (prefer older stable path) that can be overridden via route policy. Checklist: - [x] Design doc and microbenchmarks attached - [x] New scheduler hooks implemented - [x] Kernel fast-path to accept fused buffers - [x] KV-cache alignment logic added - [x] Unit tests and perf harness updates - [x] Canary feature flag and rollout plan Tests & perf: Microbenchmarks on c7g-like instances (internal lab) show throughput improvements of 1.25–1.32x for common 8k-context chat workloads when choosing INT8 fused-dequant path vs previous dynamic path selection; p95 latency reduced by ~12–20% for batched inference where dequant fusion avoided an extra memcpy; token-cost reduction observed ~10–14% across our internal benchmarks due to better batching affinity. Rollout plan: staged canary to 5% dedicated pools for 48h, validate cost and error budgets, promote to 25% then full release. Backout: feature flag and a per-route override allow immediate fallback to previous routing logic. Migration: no user-visible API changes; admin-only feature-flag defaults to off for cross-region private installs. Security/compatibility: no new network surfaces; user data stays in-process. Implementation notes: the orchestrator is intentionally tiny (~420 LOC of runtime glue); heavy lifting remains in kernel implementations. See release_notes below for selected callouts.
