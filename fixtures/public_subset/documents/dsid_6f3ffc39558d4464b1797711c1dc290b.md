Dynamic decommit gradient and fair-headroom allocator

Introduces a decommit-gradient controller and a fair-headroom allocator to reduce waste during scale-downs while preserving tenant SLAs; telemetry emits leak-adjusted utilization percentiles for better autoscaler decisions.
Motivation and summary: This PR adds a decommit-gradient controller and a fair-headroom allocator aimed at smoothing Dedicated fleet scale-downs and reducing wasted reserved capacity. Current abrupt decommits caused short-term SLA blips for tenants with bursty traffic. The decommit-gradient gradually releases reservation capacity over a tunable window based on utilization deltas and tenant priority weights. The fair-headroom allocator rebalances remaining headroom proportional to tenant earned credits and recent SLO slippage.

Design highlights and behavioral guarantees: - Decommit gradient: when a fleet/zone is marked for capacity reduction, we calculate a decaying commit fraction over the configured window (default 10m). The controller issues soft-decommit events first (allowing tenants to voluntarily release warmlets) and only escalates to hard decommits if soft steps are not observed. This reduces mass preemption and preserves KV cache locality for recent active tenants. - Fair-headroom allocator: maintains per-tenant weights (configurable via the tenant manifest) and computes redistributed headroom using a proportional fairness objective. It protects minimum floor reservations and ensures that tenants with recent SLO regressions receive extra headroom within configured caps. - Telemetry: exports leak-adjusted utilization percentiles (p50/p90/p99 of effective utilization after factoring in soft-decommit leakage) and a "decommit-residual" gauge to help autoscaler tune hysteresis.

Config example (added to dedicated/autoscaler/configs):
- decommitGradient:
    enabled: true
    window_seconds: 600
    soft_step_percent: 20
    escalation_threshold_seconds: 180
- fairHeadroom:
    enabled: true
    min_floor_per_tenant: 0.05
    redistribution_cap_percent: 40
    sllo_slack_weight: 2.0
