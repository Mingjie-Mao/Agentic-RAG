Telemetry zipper and responder-context escort for safer handoffs

Summary:
This PR introduces two complementary features for incident handoffs: a 'telemetry zipper' that consolidates fragmented telemetry pieces into a single, size-aware handoff bundle, and a 'responder-context escort' that creates ephemeral, scope-limited tokens and applies attachment sanitization policies for safe context transfer between responders or external tools.

Motivation:
Oncall handoffs frequently suffer from fragmented traces and partial logs spread across multiple services (small files, incremental snapshots, presigned attachments). That fragmentation makes triage slow and increases leakage risk when attachments travel outside the platform. The zipper reduces noise and request-count overhead; the escort enforces least-privilege context sharing with auditable tokens and an attach-sanitize policy DSL.

What changed (high level):
- telemetry zipper service: server-side component that collects telemetry fragments (logs, traces, metrics snapshots) emitted by incident-bot during an incident, collates them deterministically, and returns a single bundle URL. It performs size-aware chunking and optional compression.
- responder-context escort: new handoff flow that mints short-lived escort tokens, applies a configurable sanitization policy (regex redaction, filetype allowlist, size truncation), and records an immutable handoff audit entry.
- API: added /v1/handoffs/zip and /v1/handoffs/escort endpoints, plus SDK helpers for token exchange and bundle retrieval.
- UI: small console addition to trigger a zipper bundle on handoff and display escort token TTL and sanitization summary.
- Tests and docs: coverage for bundling logic, sanitization rules, and e2e handoff flows; added runbook hints generation for zipper bundles.

Backward compatibility and rollout:
- Both features are opt-in. Existing handoff APIs continue to work; zipper is triggered explicitly via a query param or new handoff button in the UI. Escort token issuance requires a new RBAC capability (handoff.escort). Default RBAC denies issuance until toggled by admins.
- Rollout plan: feature-flag behind 'telemetry_zipper' and 'responder_escort' flags. Canary to internal SRE first, then gradual production enablement.

Testing and validation:
- Unit tests for bundler ordering, chunking heuristics, and compression fallback.
- Integration tests for token exchange with KMS-backed signer and audit log entries.
- Load tests ensuring zipper request latency stays within 500ms P50 for typical 10-attachment handoffs.

Security considerations:
- Escort tokens are short-lived (default 5 minutes) and scoped to a single handoff id and principal.
- Sanitization policies are executed in a sandboxed worker process; unsafe attachments are blocked and replaced with a fingerprint.
- Audit entries include fingerprint hashes for blocked attachments to support future retrieval requests under compliance workflows.

Revert plan:
- Disabled via feature flag if any regressions are observed. The zipper is stateless (builds bundles from existing fragments) so disabling simply returns to per-fragment handoff with no data loss. Escort can be revoked by disabling RBAC capability and revoking outstanding tokens via audit-record TTL enforcement.
