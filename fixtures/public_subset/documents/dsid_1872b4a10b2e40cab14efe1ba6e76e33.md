response-format gating and toolcall-safety layer to stabilize streaming and OpenAI-compat

Motivation: We continue to see intermittent streaming failures when clients simultaneously request strict structured output (response_format) and tool/function calling. In practice these failures fall into two buckets: 1) early stream fragments that violate the schema and cause downstream consumers to abort, and 2) race conditions between toolcall signals and streaming token boundaries that produce truncated tool payloads. This PR introduces a lightweight gating layer plus a toolcall-safety runtime shim to reduce those failures and provide clearer error signal for OpenAI-compat consumers.

What this change does (summary): adds a response-format gating phase that validates the model's first coherent JSON token boundary before emitting application-level streaming events; introduces a toolcall-safety shim that fences tool invocation payloads until a safe flush point and falls back to non-streamed toolcall delivery when fence retries fail; maps common schema and toolcall errors to OpenAI-compatible error codes and adds a retryable error class for transient stream reassembly.

Design notes: the gating phase is intentionally minimal: we buffer up to a configurable prefix window (default 512 bytes) looking for a valid JSON token or an explicit end-of-object marker depending on declared response_format. If a valid boundary is detected, tokens are forwarded to the normal streamer; if not, the gating layer emits a structured error event that includes failure_reason and suggested_action (retry with non-strict mode or switch to non-streaming). The toolcall-safety shim keeps an idempotency token for each toolcall and enforces an explicit fence/commit handshake between the model stream and the tool-execution subsystem to avoid partial payloads. If the fence fails after N attempts, the runtime converts the toolcall into a synchronous call executed on behalf of the model and returns the result as a single non-streamed response.

Compatibility and OpenAI-compat considerations: we expose the same response_format param surface and add a tiny backward-compatible flag response_format_gating (default: on for hosted). Consumers of the OpenAI-compat wrapper will see additional error types (e.g., error.code = "streaming_schema_incomplete" or "toolcall_partial_fence") which map to documented behaviours and HTTP 409/422 codes depending on recoverability. Existing clients that ignore these codes will still receive non-streamed fallbacks.

Testing and rollout: unit and integration suites were added. Stress runs against benchmark-lab showed a ~0.8% improvement in end-to-end success rate for strict-schema workloads at 95th percentile under noisy network conditions. We staged a progressive rollout: 10% host traffic -> 50% -> 100% over one week, with automatic rollback on error rate > 1.5x baseline.

Operational notes: added observability hooks: gating_latency_ms, gate_failures_total{reason}, toolcall_fence_attempts_bucket and a dashboard in observability-pack. Docs: design sketch and migration guidance added to docs/design/response-format-gating.md and openai-compat changelog.

Related work: ENG-1210 defined the API contract changes; ENG-1357 scoped toolcall idempotency. SUP-4021 captures a customer-reported incident that motivated the synchronous fallback behavior.
