Reduce GPU workspace and peak memory via arena tuning, checkpointing, and scratch buffer refactor

Motivation: production LLM inference at large batch and sequence lengths frequently hits GPU workspace/peak memory limits, forcing use of larger instances or conservative quantization. This PR reduces peak GPU allocations and working set by combining three complementary changes: (1) a conservative activation checkpointing path for transformer blocks that trades minimal CPU recompute for up to 25-40% activation RAM reduction at long sequence lengths; (2) a unified arena allocator tuning for per-stream scratch buffers and temporary kernels, reducing fragmentation and per-request overhead; (3) refactoring scratch buffer lifetimes in the CUDA kernel wrappers so scratch allocations are reused across micro-batches inside the continuous-batching loop. Design: activation checkpointing is opt-in per model variant via a new config flag model.runtime.activation_checkpointing: "auto|off|aggressive". The default "auto" enables checkpointing when offloaded KV/cache is enabled and the estimated peak reaches configured thresholds. Arena allocator changes include: a smaller max-block size for short-lived temporaries, bucketized free-lists for 512B-8MB ranges, and a fallback slow-path that reclaims whole-stream arenas on schedule boundaries. Scratch buffer refactor centralizes buffers on the BatchWorkspace object and pins those allocations to per-GPU streams to avoid cross-stream synchronization. We added microbenchmarks and a realistic ChatML workload to the perf suite to validate both latency and throughput under mixed request sizes. Results: on our A100 40GB testbed with batch=8 and seq=4096, peak GPU memory reduced by ~36%, soft latency increase <=3% p50 and throughput steady or improved in ground-truth workloads due to reduced OOM/backoffs. Backwards compatibility and safety: the changes are gated behind feature flags and require model authors to opt into activation checkpointing for small models; we provide an automated suggestion tool in the optimizer that proposes flags based on profiling sample traces. Rollout plan: staged rollout as default for Dedicated customers after two weeks of Canary (this PR includes canary toggles).
