Introduce miniRAG CLI sandbox with capture probes and typesafe tool stubs

Motivation: provide a compact, developer-friendly CLI sandbox for rapid RAG experimentation that emphasizes stepwise debugging and minimal production friction. This PR introduces miniRAG: a zero-config CLI that wires a lightweight local indexer, a mock retriever, and a typesafe tool-stub system to demonstrate tool-calling workflows and telemetry capture probes. The target audience is product engineers and SDK consumers who want a reproducible, local-first RAG loop with clear debugging hooks.

What this PR delivers (high level):
- A CLI scaffold (bin/minirag) with subcommands: init, ingest, query, replay, and probe.
- Typesafe tool stubs (TS + Go examples) showing how to declare tool interfaces and wire results into prompts safely.
- Capture probes: a small telemetry format and runtime hooks that record prefix cache hits, retriever latencies, and model token counts to JSONL for later inspection.
- A minimal local indexer based on sqlite and a fast in-memory vector shim for demos.
- Integration tests (smoke and stepwise debug tests) and a CI workflow for the example.
- Docs and a short quickstart page on the docs site (docs/site/minirag.md) with copy-paste commands.

Why this is different: unlike our full RAG quickstarts that focus on web SDKs or devcontainers, miniRAG is intentionally CLI-first and minimal: it should run with Node 18 (or Go toolchain), no Docker required, and be useful for rapid iteration in CI or local scripts. The emphasis on capture probes is to make it easier to teach and debug production regressions by recording compact, structured traces tied to specific queries.

Compatibility and constraints:
- Works with Redwood local dev API or the hosted API (env var switch).
- Typesafe stubs compile in TS projects that use our SDK types; the Go example is intentionally small and uses explicit interfaces rather than codegen.
- Not intended for production scale; indexer is ephemeral for demos.

Runbook (how to try locally):
1) git clone && cd redwood-examples/minirag-cli
2) npm ci && npm run build (or go build for the Go sample)
3) ./bin/minirag init --example-samples
4) ./bin/minirag ingest ./examples/sample-docs --index sqlite://./data/minirag.db
5) ./bin/minirag query "Explain token routing in Redwood" --probe out/probes.jsonl
6) ./bin/minirag replay out/probes.jsonl --stepwise (replays per-probe with timings)

Testing and CI: the PR adds an integration test that runs the CLI in a temporary directory and validates that probes include expected fields. CI workflow runs lint, unit tests, integration smoke, and a quick e2e that uses the hosted API with a mocked key.

Docs and teaching notes: the docs/site/minirag.md contains a 5-minute walkthrough, a troubleshooting section for common environment issues, and a short section on how to convert probe output into a CSV for quick analysis.
