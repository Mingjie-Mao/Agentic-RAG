introduce-adaptive-observability-sampler-and-token-phase-tracing

Motivation: tracing and metric volume from large token-producing workloads has grown nonlinearly; existing static sampling wastes signal and increases cost. This PR implements an adaptive sampling mechanism that reduces telemetry volume while preserving high-fidelity traces for tokens and phases that matter (e.g., model warmup, re-ranking, long-tail token spikes). It also attaches a lightweight token-phase annotation to spans so downstream rollups and dashboards can attribute latency/cost to logical phases.

Summary of changes: added an adaptive sampler service bound into the telemetry pipeline; exposed per-route token-phase sampling policies; emitted a compact token_phase tag on spans; introduced token-phase histogram rollup and an Observability Dashboard panel for phase-aligned latency/cost heatmaps; added an alert tuning helper that uses phase-aware baselines to reduce false positives.

Key design points: the sampler uses a two-stage decision: (1) fast local heuristic based on recent token rate and phase label density, (2) low-frequency Bayesian recalibration that ensures rare phases receive minimum coverage. Sampling is cost-weighted: high-cost invocations get higher sample probability. The phase tag is intentionally compact (enum string) and stored as "phase" in span tags so existing trace indexing works.

Compatibility: new feature is gated behind a runtime flag (telemetry.adaptive_sampler.enabled) and a per-tenant policy in the console. When disabled the pipeline preserves current, stable sampling. Backwards compatibility retained for older spans without phase tags.

Results from internal canary (2-week run across staging cluster): end-to-end trace volume dropped ~36% overall, token-attributed trace volume dropped ~42% for high-throughput routes, and error/latency alert noise reduced by ~18% (measured as reduced alert count on pilot tenants). CPU overhead for the sampler is <2% p95 for the telemetry node; memory delta negligible.

Testing and rollout: unit tests added for sampler heuristics and phase propagation; e2e replay bench validates sample rates versus expected distributions; dashboard panels exercised in a manual QA run. Rollout plan: enable flag in staging for 48h, then progressive canary across 5%/25%/100% tenants with monitoring checks (trace volume, SLOs, alert counts).
