Enrich model listing endpoints with runtime hints, pricing/limits and OpenAI-compat shim

This PR extends the model listing and capability endpoints to expose runtime hints (streaming stability hints, recommended kv-cache policies, batching/latency profiles), explicit compatibility flags for OpenAI-style features (function_calling, structured_output, streaming), and per-model pricing/limits metadata (tokens_per_second_estimate, max_context_tokens, soft_rate_limit, burst_capacity). Motivation: product teams need a single discovery API to make deterministic routing and graceful fallback decisions at runtime; SDKs and the OpenAI-compat shim need canonical fields to drive feature negotiation without brittle heuristics. The change includes: 1) schema additions to /v1/models and /v1/model-catalog with new flat fields; 2) a compatibility map that lists boolean flags and a deprecation & aliases map for older capabilities; 3) streaming stability hint tokens that indicate recommended chunking size and backoff policy; 4) pricing/limits fields surfaced for billing and client-side throttling; 5) an OpenAI compatibility layer update that maps Redwood capability names to OpenAI equivalents and exposes a single compatibility_score to help automated routing. Backwards compatibility: added fields are optional and default to safe values to avoid client breakage. See release_notes for migration guidance.
Added unit tests for serializer/deserialize, compatibility mapping tests, and integration test that exercises routing policy selection using new compatibility_score and streaming_hints. Load test validated tokens_per_second estimates under mixed batch sizes and reported within 10% of observed throughput.
