Add onboard previewer for impact statements and compact diff bundles

Motivation: Onboarding signals (profile deltas, perf regressions, metadata drift) are noisy; product and platform teams need a concise, previewable artifact that summarizes impact and provides a roll-backable draft release bundle before a full publish. This PR introduces an 'onboard previewer' that synthesizes compact diff bundles and an affordance-focused impact statement so stakeholders can review and sign off on releases without full provisioning. Summary: - Adds a preview CLI and a lightweight HTTP preview service that produces a compact diffs bundle (sharded, gzipped) plus an auto-generated impact statement summarizing performance deltas, compatibility hints, and suggested rollout policies. - Integrates a stratified sample-based delta scorer to prioritize examples where QoE diverges. - Produces signed preview artifacts so CI and SRE can verify immutability and enable rollbackable release drafts. - Adds a small web preview panel for quick QA and a README + docs for usage. Key design notes: - Compact diff bundle: delta-only manifest plus sampled telemetry snippets and a small binary patch for large metadata blobs; format is intentionally compact to enable quick transfer to reviewers and to archive as signed preview artifacts. - Sample strategy: stratified sampling across latency, token-length buckets, and failure modes; default 20% sample budget configurable via CLI flag. - Impact statement: affordance-first, includes numeric delta summaries (latency, token cost, pass-rate), notes on quantization/precision changes, and recommended rollout (canary percent + fallback model). - Rollbackable release drafts: preview artifacts are stored in the registry as 'draft:preview/<id>' with signatures and a small manifest that can be atomically swapped to 'release/<version>' by the release pipeline. Checklist: - [x] CLI + service implemented - [x] Sampler and delta scorer implemented - [x] Compact diff serializer and template renderer added - [x] Signed artifact schema and signing helper included (HSM/KMS pluggable) - [x] Docs and quickstart added - [x] Integration tests (e2e preview -> sign -> verify) added Compatibility and migration: - No breaking changes to existing onboard manifests. - Default sampling budget is conservative; operators can opt-in to full sample mode. - Signing integrates with existing KMS abstraction; if no KMS configured the previewer emits unsigned artifacts but notes the risk in the output. How to use: - CLI: onboard-preview generate --manifest path/to/manifest.yaml --sample-budget 0.2 --out preview-123.tar.gz - Web: POST the manifest to /api/preview and follow the returned preview ID to the UI. - To promote a preview to a draft release, run: onboard-preview promote --preview-id preview-123 --target draft/v1.0.1 Security and SRE notes: - Previewer emits a signed metadata stamp (if KMS present) and a short provenance JSON included in the artifact. - The CI workflow has an optional step to verify signatures and run a light smoke-run on Dedicated hardware. Performance: - The sampler runs in O(n) over telemetry shards; renderer is streaming-friendly and memory-bounded. - Typical end-to-end preview generation for moderate manifests (~1000 samples) completes in ~45s on a 4CPU job (numbers in docs). Caveats: - The previewer is intentionally opinionated about sampling; teams with strict deterministic QA should run full evaluation separately. - Signed preview artifacts are persisted but treated as ephemeral until promoted to a signed release.
