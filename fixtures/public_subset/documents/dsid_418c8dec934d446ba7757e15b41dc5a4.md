Introduce key-reconciliation-proxy and rotation dry-run mode for HSM-backed KMS

Motivation: Customers running Redwood Private in regulated environments requested a non-destructive way to validate HSM key promotions and certificate rotations before committing changes to production. This PR introduces a key-reconciliation proxy and a cluster-scoped Helm + Terraform upgrade path that supports a 'dry-run' rotation mode, comprehensive telemetry for sealed-secrets unseal flows, and safe staged rollback hooks for on-prem HSM promotions. Design summary: 1) key-reconciliation-proxy: a lightweight sidecar/proxy that intercepts KMS key-promote/rotate API calls and performs a reconciliation pass against Vault/SealedSecrets annotations and the HSM key inventory. In dry-run mode it simulates the promotion steps, writes a reconciled action plan to a k8s ConfigMap, and emits structured telemetry (promotions.plan, promotions.risk_score, promotions.conflicts) to the observability pipeline. 2) helm chart changes: new values.yaml flags (rotation.dryRun, reconciliation.enabled, reconciliation.maxParallel) and templated Job + ConfigMap objects to stage plans. 3) terraform module: add kms_key_labeling and signer_proxy resources to the private-installer module to ensure HSM key metadata is consistent across zones and to allow atomic tagging during staged rollouts. 4) rollback hooks: operator-level finalizers and a reversible promotion transaction that can be rolled back by applying the generated action plan in reverse; also adds automatic safe-grace periods and an emergency abort controller. 5) sealing/unsealing telemetry: add hooks into sealed-secrets controller to emit anonymized unseal durations and KMS unwrap success/failure counts to help detect slow HSM paths. Backwards compatibility: dry-run is opt-in and defaults off. For existing installs the module is additive: no automatic key re-labeling unless explicitly enabled via the terraform var 'enable_reconcile_proxy'. Implementation highlights: - New binary: reconciler-proxy (Go) with a small runtime (5MB binary) that can run as a DaemonSet or as a sidecar. It exposes a PREVIEW API for generating promotion plans. - Helm: chart/values.yaml, templates/reconciler-configmap.yaml, templates/promotion-job.yaml, templates/rollback-cronjob.yaml. - Terraform: modules/kms-reconcile/main.tf + variables and example usage in examples/kms-reconcile. - Operator: upgrade to installer-operator v0.14.2 with new controllers for PromotionPlan CRD (CRD included). - Tests: unit tests for proxy logic, integration test harness that runs an air-gapped K8s cluster with HSM emulator and validates dry-run vs live promotion flows. Migration and rollout: document a staged rollout plan in docs/upgrade/kms-reconcile.md (included). Suggested rollout: 1) deploy reconciler-proxy in dry-run mode, 2) run a handful of migrations to inspect generated plans, 3) enable promotion dry-run verification gates in console, 4) once satisfied, flip rotation.dryRun=false and run a controlled promotion. Security notes: proxies authenticate to HSM via existing KMS credentials; the PR adds audit logging and a short-lived signing key for plan approvals. Testing and verification: run the included terraform example in staging (see README) and follow test plan below. This PR is designed to be non-breaking and to make on-prem upgrades safer by providing a reversible, observable promotion path.

1) Deploy chart with rotation.dryRun=true in staging. 2) Run terraform example to label keys and create PromotionPlan. 3) Inspect generated ConfigMap plan, verify no key material. 4) Run integration test to simulate HSM promotion with emulator. 5) Flip dryRun=false in a controlled window to perform live promotion.
PromotionPlan CRD contains reversible steps. The rollback controller applies steps in reverse and uses HSM-safe abort tokens. In an emergency: 1) set promotionplan.spec.abort=true 2) controller will revert labeling and re-apply previous signer-config via terraform module with force=false guardrails.
