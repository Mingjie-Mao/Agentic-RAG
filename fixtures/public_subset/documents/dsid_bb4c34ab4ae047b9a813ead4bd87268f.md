add init and rollback hooks, values schema, and templating for private installer helm chart

Motivation: Add formal values schema, init hook jobs and a rollback hook to the 'private' Helm chart used by Redwood Private installer to support deterministic on-prem upgrades, database migrations, and optional HSM/KMS init sequences. This PR introduces a new values.schema.json to validate user-provided values at installation time, a templated init-job that runs pre-upgrade migration and secret bootstrap steps, and a rollback hook job that runs only when Helm rollback is invoked. Changes also extend templates to support conditional KMS/HSM credentials, refactor the clusterRole/role templates to scope RBAC for init jobs, and add notes + tests for upgrade/rollback flows. Checklist: 1) Add values.schema.json with explicit types and enum constraints for storage, network and kms settings; 2) Create templates/init-job.yaml as a pre-upgrade hook (helm.sh/hook: pre-upgrade, weight: "-5"); 3) Create templates/hooks/rollback-job.yaml as a post-rollback hook; 4) Update Chart.yaml and README with configuration examples and migration notes; 5) Add unit tests (helm template + schema validation) and a small e2e playground script for local Vagrant/OpenShift testing. Migration notes: users running private installations with custom storage or kms settings should add the new `initJobs.enabled` flag to values or the chart will explicitly fail schema validation. Rollback behavior: rollback hook is opt-in via `hooks.rollback.enabled` to avoid unexpected side effects in cluster-managed environments. Testing summary: ran chart linting and schema validation in CI, fixed an initial deprecated apiVersion issue for batch/v1 Job in older clusters, and iterated on RBAC to limit permissions. See ENG-1823 and PM-87 for product acceptance criteria. Links: https://linear.app/redwood/issue/ENG-1823, https://docs.redwood.ai/private/upgrade-guide (internal).
