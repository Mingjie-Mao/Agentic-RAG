Automate attestation + notarization for private-installer Helm/Terraform releases

Motivation:
We need reproducible, auditable release artifacts for Private deployments (VPC/on-prem installer). This PR wires up automated attestation and notarization into the existing release pipelines so that Helm charts, Terraform modules, and the on-prem installer tarballs are (1) reproducibly built, (2) cryptographically attested for build provenance, and (3) notarized with a timestamped signature stored alongside release manifests.

What this changes (summary):
- Adds a CI pipeline that produces deterministic build artifacts, generates SBOMs, and emits in-toto attestations for: Helm chart bundle, terraform modules, and the private-installer tarball.
- Integrates a notarization step that signs artifacts using a hardware-backed key (KMS/HSM integration stubbed for e2e; sees scripts/notarize.sh).
- Enhances release manifest generator to include provenance links (attestation uri, sbom uri, signature digest) and to publish a compact release-manifest.json to the releases bucket.
- Updates Helm chart metadata (Chart.yaml) with immutable digest fields and chart provenance annotations consumed by the installer.
- Terraform module releases now include a module_manifest.json with module version, provider pinning, and attestation reference.
- Adds a rollback-safe release marker: when a bad release is detected we can toggle 'active_release' in the manifest which the installer reads for safe rollback.

Design notes and tradeoffs:
- We use in-toto attestations (simple layout) instead of full SLSA pipeline enforcement for now to reduce blast radius and unblock ops. Future work will add stricter SLSA levels.
- Notarization uses an HSM-backed signing flow where the key material is kept in KMS. For CI we use a test key; the pipeline includes a gate to require a production KMS binding for production releases.
- Deterministic builds: we pin builder images and canonicalize timestamps when generating tarballs and charts to minimize non-determinism. This increases build complexity but is necessary for reproducible provenance.
