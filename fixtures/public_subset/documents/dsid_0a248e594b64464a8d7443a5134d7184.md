Add RAG-guided assertion harness and CI runner quickstart

Context: Teams building RAG flows often lack deterministic, CI-friendly checks for regressions introduced by model, prompt, or index changes. This quickstart introduces a lightweight assertion harness and CI runner that:
(1) defines per-scenario assertions against retrievals and generated outputs,
(2) snapshots index and retriever behavior for deterministic tests, and
(3) runs in a GitHub Actions job to surface RAG regressions early. This PR contains a reference implementation (Python runner + small TypeScript tool stub), docs, and a CI workflow.

Motivation: prevent subtle retrieval+generation regressions from reaching production—especially for rule-driven features (billing summaries, policy classification, and short answers).

What this adds:
- assertion schema (YAML): scenario metadata, retriever snapshot refs, expected-kv assertions (approx_string_match, top_k_presence)
- runner (runner.py): reproducible local test harness that can run against a mocked vector store or a live sandbox index, produces TAP-style output and a compact JSON report
- template tool stubs (TS/py) for tool-calling tests where the agent should call external services
- GitHub Actions CI job (ci/assertions.yml): runs quick smoke assertions on push, full-suite on nightly or manual workflow
- README with recipes: local dev flow, CI thresholds, how to pin snapshot hashes and update golden outputs, sample Linear tickets to file when failures require triage

Usage (local):
1) pip install -r requirements-dev.txt
2) python runner.py --scenario examples/policy-summary.yaml --mode mock
3) runner produces results/report.json and exit code 0 on success

Commands (CI):
- name: Run RAG assertions
  run: python runner.py --suite ci/smoke-suite.yaml --mode live --output results/assertions.json

Notes on determinism: the harness snapshots dense-index keys and retriever seeds; tests include a small "delta tolerance" field to allow harmless tokenization/embedding drift while still failing on semantic regressions. See README for how to rebaseline.

Related Linear: ENG-4398 (assertion runner), ENG-4410 (CI integration).

Risk assessment: low—this is a developer-facing quickstart and does not touch runtime serving.

Migration: N/A for production infra.

Troubleshooting:
- If CI shows index drift, run `python runner.py --recreate-snapshot` locally and open a new Linear with attached report.
- For flaky generation assertions, increase `approx_string_match.threshold` or pin model variant in scenario.
