Add per-call auth hooks and idempotent stream retry operator

Summary: This PR introduces two complementary ergonomics features to the TypeScript SDK: (1) a per-call auth hook API that allows callers to run synchronous/async logic to refresh or mutate auth metadata immediately before any RPC attempt, and (2) a StreamRetryOperator that implements idempotent retry semantics for streaming endpoints. Motivation: production streaming workloads hit two recurring issues: short-lived credentials requiring a per-attempt refresh, and partially-applied streams that should be retried safely without duplicating side effects. The existing SDK had ad-hoc patterns in userland which were error-prone. This PR centralizes the behavior, provides safe defaults, exposes strong types, and ships cross-SDK coordination notes for Python/Go.
Design and motivation:
- Per-call auth hook: an opt-in callback (auth.perCallHook) executed before each transport attempt; it receives contextual request metadata and may return additional headers. This replaces common patterns that attempted to refresh tokens in background timers, reducing edge-case 401s on long-running streams.
- StreamRetryOperator: composable operator that can be attached to streaming routes. It supports idempotency keys, checkpointed event replay for idempotent frames, and a bounded retry policy (maxAttempts, backoff). The operator only retries when the route is registered as idempotent or when an idempotencyKey is provided by the caller.

Migration notes:
- This feature is opt-in. Existing code paths are unchanged unless callers pass `auth.perCallHook` or attach `streamRetry: {enabled: true}` to the request options. Suggested minimal migration: provide an idempotency key for server endpoints that perform side effects. Example: client.chat.stream({..., idempotencyKey: createUuid(), streamRetry: {enabled: true}})
Telemetry and troubleshooting:
- New metrics are emitted only when the retry operator is active. If customers see a high `sdk.stream.retries` count, it indicates transient transport issues or auth failures. The per-call hook has a per-call latency metric to surface expensive auth calls.
Backward compatibility: No breaking changes. All public APIs are opt-in and have fallbacks.
