atomic release staging, Helm preflight hooks, and compressed release manifests for safer private-installer rollouts

Motivation: private on‑prem/VPC upgrades require greater atomicity and preflight validation to avoid partial rollouts and long rollback windows. This PR introduces a small release staging layer, Helm preflight hooks (pre-install/pre-upgrade/validate), and a compact compression/packing step for release manifests and provenance files so that the installer can stage an entire release snapshot atomically and validate it before switching the live release pointer. Design summary: 1) release-stager: an ephemeral staging area in S3/GCS with an atomic 'active' pointer object; publish pipeline uploads a packed, signed archive and a JSON index; after successful post-signature validations the pipeline atomically swaps a symlink-style object (bucket key replace) to make the new release active; 2) manifest packing: index_pack.go creates deterministic tar stream, zstd compresses blobs with level 3 for speed, and the pack includes SHA256 provenance metadata for each entry to simplify verification during installs; 3) Helm preflight hooks: small Helm hooks run before install/upgrade to validate node resources, image accessibility, KMS availability, and required CRDs; failures are surfaced early and abort the Helm transaction; 4) installer/rollback: upgrade tool gains a two-phase apply with an automatic dry-run validation and a deterministic rollback plan derived from the staged index so rollbacks are fast and do not rely on ad-hoc heuristics. CI changes: new pipeline job ci/pipelines/release-stager.yml validates packing/compression, runs signature verification, and performs a smoke deploy to minikube in under 6 minutes. Security: signing routine ensures reproducible tar order before cosign signing and inserts a small attestation with build-info and builder git-ref. Backwards compatibility: published archives include both packed zstd artifact and legacy uncompressed blobs to allow older private-installer clients to continue fetching if necessary; rollout plan includes a two-week dual-read window before deprecating legacy path. Testing: unit tests for packer and signature validator, integration tests for staged swap and Helm preflight, and manual canary in a staging VPC. Rollout: merge -> pipeline produces staged artifact -> run canary promotion job -> after 24h and monitoring approval, auto-swap active pointer for production. See release_notes for more details and migration steps.

- Introduces atomic release staging: publishes a packed, signed artifact and atomically swaps the active release pointer in object storage.
- Adds deterministic packing and zstd compression for release manifests and provenance, reducing release size and improving upload latency.
- Adds Helm preflight hooks (pre-install, pre-upgrade) to validate cluster preconditions and abort unsafe rollouts.
- Upgrade tool now generates a deterministic rollback plan from staged indexes to make rollbacks reliable and fast.
- Backwards compatibility: staged artifacts include legacy uncompressed blobs for a configurable dual-read window.
- CI: new release-stager pipeline with minikube smoke test and signature validation.
Unit: packer deterministic order, zstd roundtrip, signature verify. Integration: staged swap + Helm preflight on minikube. Manual: canary promoted to staging VPC and monitored for 48 hours before prod promotion.
1) Operators: update terraform module for release bucket to enable versioning and object-lock suggested setting. 2) If you run on very old installer clients: keep legacy-read enabled (env RELEASE_LEGACY_READ=true) until clients are upgraded. 3) To opt into atomic swap immediately, set release_stager_enabled = true in tf module and run apply. 4) To roll back a staged release: use tools/upgrade/plan_and_rollback --release <name> --rollback-to <timestamp> which calculates deterministic steps from the packed index.
This PR is intentionally conservative about compression level to prioritize install speed on constrained customer networks. We plan to introduce optional higher compression for air-gapped distribution in a follow-up change.
If a production install reports 'manifest-signature-mismatch' after promotion, fall back to previous active pointer (stager.undo_swap) and open SUP ticket; artifacts remain in the staging bucket for forensic analysis.
