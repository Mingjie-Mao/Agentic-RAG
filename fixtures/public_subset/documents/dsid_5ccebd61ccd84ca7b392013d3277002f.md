Add hardware-timestamp tracepoints and synthetic-replay microbench for kernel latency and tile occupancy

Motivation: pinpoint sub-kernel latency variance and per-tile occupancy skew seen during continuous batching on long sequences. This PR adds lightweight hardware-timestamp tracepoints around kernel launches, a small lock-free per-tile occupancy counter, and a deterministic synthetic-replay microbenchmark that replays recorded request traces at controlled concurrency for stable profiling. Changes are gated behind runtime flags so there is zero overhead when disabled. High-level summary: 1) runtime/tracing/hw_timestamp_trace.h/.cc implements RAII-style trace scopes that capture wallclock and GPU hw timestamps when available and annotate the internal timeline with span ids, 2) runtime/scheduler/tile_counter.h/.cc introduces a cache-friendly per-tile occupancy counter sampled by the scheduler to record occupancy distributions, 3) tools/replay_bench parses a compressed request trace and replays with configurable arrival patterns and concurrency to exercise the batching scheduler reproducibly, 4) observability/exporters/perf_dashboard_exporter.py converts trace output into a bundled JSON for the perf dashboard including per-kernel latency histograms and per-tile occupancy heatmaps, 5) added unit and microbench tests and CI job to validate reproducible runs. Checklist: - [x] add hw timestamp trace scopes - [x] implement per-tile occupancy counters - [x] implement synthetic replay bench - [x] export summarized metrics for dashboard - [x] add CI microbench job - [x] update docs and example traces. Usage notes: enable tracing with REDWOOD_TRACING=hw_timestamp or use the scheduler flag --enable-tile-counters. Replay tool accepts --trace-file and --concurrency flags. Recorded traces are compressed with a simple run-length encoding to keep artifacts small. Backwards compatibility: tracing is opt-in and defaults to off so production behavior is unchanged. Performance: measured overhead with tracing on is ~2-3% for short sequences and up to 7% during heavy kernel churn; with tracing off overhead is nil. See release notes for more details.
