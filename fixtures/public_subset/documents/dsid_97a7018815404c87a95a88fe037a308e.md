introduce-stationarity-aware-canary-guard

Motivation: Canary detectors trained on stationary traffic often raise false positives during modal traffic shifts (campaigns, timezones, regional events). This PR adds a Stationarity-Aware Canary Guard that dynamically adjusts detection thresholds and probe scheduling based on rolling tests for distribution stationarity and tail-heaviness. High level: 1) Introduce a lightweight stationarity score computed per route using rolling-window ADF and KPSS heuristics plus a normalized kurtosis tail indicator, 2) Use the stationarity score to choose between strict percentile-based detectors or relaxed, probe-augmented comparison windows, 3) Add a traffic-modality classifier that tags slices (steady, diurnal, bursty, ramp) and feeds into the probe scheduler to avoid misleading short-lived alerts, 4) Integrate with rollout gating so that canaries under non-stationary regimes use conservative cutover budgets, synthetic probe amplification, and a rollback leash. Changes include: new perf-canary modules (stationarity scoring, modality classifier, probe-rescheduler), runtime hooks for route-level metadata, console dashboard widgets for stationarity heatmaps and decision rationale, end-to-end tests and a traffic-sim harness to validate behavior under synthetic campaigns. Backwards compatibility: detectors default to previous behavior when stationarity module is disabled by feature flag. Why now: we saw two incidents where promotional traffic spikes caused noisy canary failures and unnecessary rollbacks; this approach reduces churn while preserving sensitivity to true regressions. Checklist: (1) Unit tests for statistical routines added, (2) Integration tests against perf-canary harness added, (3) Feature-flag gated rollout, (4) Docstrings and console text provided, (5) Observability: traces and metric labels included for explainability. Deployment plan: enable behind a runtime flag in canary staging for two weeks, monitor false positive rate and rollback frequency, then roll to prod if FPR drops >= 40% without missing known regressions. Impact: expected reduction in false canary aborts during non-stationary periods, small CPU cost for lightweight stationarity heuristics, improved developer signal-to-noise.
