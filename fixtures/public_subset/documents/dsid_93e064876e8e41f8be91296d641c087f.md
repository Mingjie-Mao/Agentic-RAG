Autotuned throttle + prefetch coordinator to reduce streaming first-byte latency

Motivation: streaming requests under mixed workloads exhibited spiky first-byte latency (TTFB) and poor tail behavior when KV prefetches and microbatch drains collided with kernel selection. This PR introduces an autotuned coordinator that couples per-stream throttle windows with probabilistic KV prefetch warming and drain prioritization, aiming to reduce median and tail TTFB without regressing throughput. Key ideas: 1) Per-stream latency budgets derived from SLA config and recent percentiles drive a soft throttle that caps emission window size and dynamically stretches inter-token yield points. 2) A lightweight prefetch score uses recent KV cache hit/miss ratios, token generation velocity, and kernel warm indicators to trigger prefetches earlier for likely-follow prefixes. 3) Cooperative microbatch drain ordering: streams with tighter budgets and active prefetches are prioritized for kernel allocation and KV reheating. 4) Autotuner observes background load signals (device utilization, kernel queue depth, histogram of token latencies) and adjusts throttle aggressiveness and prefetch lead-time using exponential moving averages. This was implemented with low-overhead data structures and fast-path checks to avoid impacting the hot token loop. The description below outlines changes, benchmarks, tests and rollout plan.

Throughput unchanged within +/-3% under steady load. In low-load scenarios p50 improved ~10ms. Benchmarks include cold-KV, warm-KV and interleaved arrivals.
