Introduce token lifecycle retention mapper and tiered alert funnel

Motivation: long-tail token-level metrics consume disproportionate storage and drive noisy alerts. Customers and SRE teams asked for smarter retention and alert escalation that understands token lifecycle (prefetch/warm/cache/regenerated) so we can reduce noise while preserving actionable signals. This PR introduces a retention-aware token lifecycle mapper, metric rollups that age buckets based on lifecycle, and a tiered alert funnel (critical/high/medium/low) which escalates alerts using retention-informed de-duplication and suppression windows.

Summary of changes: added a token lifecycle enrichment stage that annotates traces and metrics with token.lifecycle and token.retention_tier, implemented downsampled histogram rollups keyed by lifecycle state, added a dashboard and alert playbook that drives a tiered funnel with progressive escalation delays, and integrated sampling hints into the log-sampler so long-tail tokens are sampled less aggressively after retention-window expiry. Also updated docs and end-to-end tests.

Testing notes: unit test coverage added for lifecycle heuristics and histogram rollup invariants. Integration tests run a synthetic workload that simulates prefetch, normal, and regenerate flows; verifies that retention tiers move tokens from hot->warm->cold and that rollups compact older tiers. Staging e2e included a small customer workload to validate alert funnel behaviour and ensure no regressions in metrics cardinality.

Rollout plan: gated behind feature flag obs.retention_funnel. Stage 1 (dev/staging): enabled for internal tenants only for 72h. Stage 2: enabled for 10% of hosted traffic, monitor token cardinality and alert noise. Stage 3: progressive ramp to 100% with default conservative retention windows. The alert funnel is enabled in a muted mode (record-only) for 48h prior to stateful suppression.

Backward compatibility: ingestion proto adds optional token.lifecycle and token.retention_tier fields; older clients continue to function. Rollups are additive; metric names include new lifecycle label but we still export aggregate (no-lifecycle) series for customers that do not opt-in.

Related work: ties to ENG-1974 (adaptive-sampling), ENG-2021 (alert-coalescer), and docs update PRs for the observability playbook.
