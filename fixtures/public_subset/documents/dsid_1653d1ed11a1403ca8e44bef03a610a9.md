per-route function-call telemetry and JSONL output tagging

Motivation: customers using function/tool-calling and structured output have limited ability to correlate tool calls to per-route metrics, and streaming JSONL outputs lack stable tags for downstream log processors. This PR attaches per-route metric tags to function-call events, enriches JSONL streaming output with consistent telemetry headers, and adds trace propagation across the OpenAI-compat adapter layer. Changes aim to improve observability without changing public API semantics. Summary of changes: 1) Add per-route "route.tags" metadata to function-call events emitted by the gateway and runtime; 2) Emit a compact telemetry header ("rwid, srv, route, call_idx") at the start of streaming JSONL chunks to enable log reassembly; 3) Propagate distributed trace context and span IDs into function-call instrumentation and structured logs; 4) Update openai-compat adapter to translate OpenAI-style "request_id" into rwid and include route tags for compatibility; 5) Add unit and integration tests covering streaming reassembly and metric label cardinality limits; 6) Add doc comments and console notes for admins about limiting custom route tags. Checklist: - [x] Add telemetry header and tests - [x] Preserve streaming shape for openai-compat clients - [x] Ensure route tag cardinality cap (100) enforced - [x] Add end-to-end smoke test against mock tool runner - [x] Update docs and changelog Impact: no user-facing API change; observability improvements are additive. Rollout plan: feature gated behind experiment flag "obs.route_tags_tool_calls" for three days in canary, then staged rollout to 25% traffic, then full rollout assuming no regressions. Monitoring: added alerts for spike in unique route tags and increased rate of incomplete streams.
