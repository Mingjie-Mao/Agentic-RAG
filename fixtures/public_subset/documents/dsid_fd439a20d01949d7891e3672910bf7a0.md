Introduce token-flow-regulator to co-schedule kernels and KV admission for smoother prefill bursts

Motivation: production traffic shows frequent short prefill bursts that cause decode-stage stalls and late tail latency spikes. Existing backpressure relies on coarse token credits and reactive KV eviction which either underutilizes kernels or thrashes the KV cache. This change introduces a token-flow-regulator subsystem that (1) exposes a lightweight admission controller for KV cache residency, (2) co-schedules prefill and decode kernel slices to avoid head-of-line bursts, and (3) introduces a pacing policy that converts microbursts into shaped windows that downstream decode kernels can absorb.

Design summary: the token-flow-regulator sits in the serving runtime pipeline between request intake and kernel dispatch. It tracks in-flight token windows, maintains a small moving-window estimator of per-request sequence progress, and emits two control signals: KV admission (allow/hold/evict-hint) and kernel-slot allocation hints (slice-size, priority). The regulator uses a credit refill algorithm with a burst-tolerance factor to allow short spikes without triggering KV admission evictions. Kernel co-scheduling uses those hints to place small prefill slices adjacent to pending decode slices on the same GPU when beneficial (reduces kernel launch overhead and warms KV cache).

What changed (high level): added runtime/scheduler/token_flow_regulator.cpp, runtime/scheduler/token_flow_regulator.h; implemented KV admission policy in runtime/kvcache/admission_controller.rs; extended kernel dispatcher to accept slice hints in runtime/worker/kernel_dispatcher.cpp; added integration tests and a microbenchmark harness in bench/token_flow_bench.py; updated docs and operator knobs in docs/perf/token_flow_regulator.md.

Performance summary: in internal prefill-heavy traces the change reduces 99th-percentile completion latency for short conversations by ~14% and reduces KV cache churn measured as eviction rate by ~28%. End-to-end token/sec throughput on stable long conversations is neutral (-1% within variance). See bench/token_flow_report.md for detailed numbers and flamegraphs.

Operational notes: the feature is behind a feature flag and default-off for Dedicated clusters. Operators can tune runtime.token_flow_regulator.max_burst_tokens and .burst_tolerance. Rolling upgrade path: enable flag in canary subset, monitor kvcache.evictions and serving.tail_latency_99th. Rollback: flip feature flag or revert the feature gate; admission_controller changes do not change on-disk cache format.

Related: complements recent kernel slice optimizations; differs from speculative prefill in that this is admission and pacing-first (not speculative decode).
