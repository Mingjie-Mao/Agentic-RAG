Hybrid coldstart emulator with KV-cache priming reporter and epochal tail sampler

Adds a hybrid cold-start emulator for mixed warm/cold KV-cache scenarios and a reporter that quantifies priming efficacy across epochs; useful for batch-sizing and warmup policy tuning.
Motivation: subtle cold-start effects from KV-cache priming and heterogeneous sequence-length mixes cause non-linear p95 spikes in real workloads. This PR adds a hybrid coldstart emulator that models a mix of freshly spawned and warmed workers, an epochal tail sampler to surface long-tail interactions, and a KV-cache priming reporter that measures how many tokens and requests are required to reach steady-state hit rates. Design: the emulator runs synthetic sessions with configurable warm/warmup ratios, variable primer strategies (prefix-only, full-prefix, distributed-primer), and injects background load to mimic noisy co-tenancy. The reporter aggregates per-epoch hit-rate curves, amortized priming cost (tokens/sec and GPU cycles proxy), and p50/p95/p99 latency deltas before/after priming. Included is a small harness to replay production sampling traces to seed the primer and validate fidelity. Checklist: - [x] implement emulator core and session scheduler - [x] add epochal tail sampler with configurable retention window - [x] implement KV priming reporter and CSV/JSON exports - [x] wire CI microbench that validates no regressions on core runner path - [x] add docs/README with how to reproduce experiments - [x] add unit tests for sampler and reporter heuristics How to run locally: run ./bench_runner --config=examples/hybrid_coldstart.yaml --epochs=10 --emit-reports=out/ and then python tools/kv_report_visualize.py out/*.json to get priming curves. Backwards compatibility: emulator and reporter are opt-in via config flags; defaults preserve existing runners. Impact: helps SRE and runtime teams pick warmup budgets and batching strategies; surfaced a small scheduling inefficiency that we fixed (see commits).
