Instrument token lifecycle events, collapse span-dependency graph, and add SLO slope detector with Token Sankey dashboard

Context and motivation: Customers and internal teams have repeatedly asked for better attribution of long-tail token cost and tail latency to concrete lifecycle events (allocation, reuse, eviction) and for a way to identify causally related spans in dense microservice graphs. Static threshold alerts were generating noise during gradual traffic shifts. This PR introduces three complementary capabilities: 1) token lifecycle event instrumentation (lifecycle tags and structured event stream), 2) a collapsed span-dependency graph that synthesizes repeated RPC edges into a single dependency with counts, and 3) an SLO slope detector alerting rule that triggers on sustained upward slope in 95th-token-cost or token-latency over a sliding window.

What I changed (high level):
- telemetry: emit telemetry.token_lifecycle_events (structured events with life_stage: allocated|reused|evicted, reason tags for eviction/coldstart, and token_cost_micros). Also emit telemetry.token_entropy and telemetry.kv_cache_hotness.
- tracing: add span dependency synthesizer that produces tracing.span_dependency.edges_count and tracing.span_dependency.collapse_reason. Collapses repeated RPC edges within a session to reduce cardinality and make graphs readable in the UI.
- dashboards: new dashboard panels under Observability > Token Economics: "Token Lifecycle Sankey" (flows from allocation -> reuse -> eviction, grouped by model and route), "Dependency Collapse Explorer" (collapsed graph with counts), and "SLO Slope Detector" widget showing fitted slope and alert window.
- alerting: introduce slo-slope-detector rule that compares rolling-window linear fit on p95 token cost and token-latency and fires when slope > threshold and R^2 > 0.6 for N consecutive windows. This replaces two noisy static thresholds for the hosted API routes.
- logging: structured log enrichment with event_type and lifecycle_id to correlate logs / traces / metrics more easily in joins.
- docs: added a HOWTO for using the Token Sankey and best practices for slope thresholds.

Why this is different: The lifecycle events give a first-class primitive for attributing per-token cost/latency to actual runtime lifecycle stages rather than just route/model. The dependency collapse reduces noise from chat/chain workloads where the same RPCs are repeated in a session. The slope detector is tuned for gradual regressions (e.g., model drift, quantization regressions, infra degradation) rather than transient spikes. Together these reduce alert noise and accelerate root cause discovery.
