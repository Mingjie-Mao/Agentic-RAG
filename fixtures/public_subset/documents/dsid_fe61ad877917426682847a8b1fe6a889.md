Add dependency rollback actuator and lightweight build adapter to stabilize presubmit

Context: Over the last month multiple presubmit flakes were traced to partial dependency rotations and large toolchain bootstraps that race on networked artifact stores. This PR introduces two related mitigations: (1) a dependency rollback actuator that can detect a failing presubmit cohort after a dep rotation and automatically pin the presubmit runner to the last-known-good dependency snapshot, and (2) a lightweight build adapter that replaces the legacy monolithic bootstrap path for presubmit lanes with a thin, cache-first initializer to dramatically reduce I/O and start time. Motivation: reduce noisy presubmit failures during large dependency updates, speed feedback loops for engineers, and lower CI egress/IO costs. Summary of changes: - infra/ci/rollback/actuator.go: new actuator and reconciliation loop, with backoff and safe-mode toggle. - infra/ci/rollback/README.md: operational runbook and commands for manual rollback+inspect. - infra/ci/build_adapter/adapter.py: lightweight adapter with two-stage cache warm path. - ci/workflows/presubmit.yml: wiring to call adapter for targeted lanes and a feature flag gate for actuator. - scripts/dep-snapshot-tool: helper to create and list snapshots used by actuator. - internal/telemetry/ci_metrics: added counters for rollback events and adapter warm hits. - tests/ci_simulation_test.go: simulation harness for rotating deps and validating actuator behavior. Commits: 1) add rollback actuator and snapshot CLI 2) implement lightweight adapter and wire presubmit lanes 3) add telemetry and tests 4) docs/runbook and minor refactors Review checklist (what I validated): - Unit tests added for actuator reconciliation and adapter warm path - Integration simulation validates rollback triggers on 2 consecutive cohort failures - Manual smoke: exercised on staging org with a synthetic dep rotation, verified automatic pin and then unpin after snapshot promotion - Load: validated adapter reduces presubmit bootstrap median by ~48% on our internal sample workloads Rollout plan: feature-flag gated on presubmit; staged enablement across teams (platform -> core-services -> rest) over a week; actuator starts in "observe" mode, then "enforce" after 48h stable. Backports: small backport requested for the release/* branch for customers pinned to older presubmit infra (ENG-2147). Risk and mitigations: actuator holds a safe-mode toggle, exponential backoff to avoid oscillation, and a manual override in runbook. The adapter adds a compatibility shim for runners that still expect the old bootstrap format. Operational notes: see infra/ci/rollback/README.md for runbook and alert tuning. CI: initial run showed lint failure due to import ordering, fixed in second commit; flaky integration test triggered and was stabilized by increasing the simulation timeout.
